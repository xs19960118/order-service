# 多数据源配置说明

## 概述

本项目配置了三个 MySQL 数据源，分别用于不同的业务场景：

1. **Boss 数据源（主）** - 订单服务主要业务数据
2. **CRM 数据源** - 客户关系管理数据
3. **Report 数据源** - 报表统计数据

## 配置文件

### application.yml 配置

```yaml
spring:
  datasource:
    # Boss 数据库（主数据源）
    boss:
      jdbc-url: jdbc:mysql://host:3306/portal_boss_sit
      username: portal_boss_sit
      password: ******
      driver-class-name: com.mysql.cj.jdbc.Driver
      
    # CRM 数据库
    crm:
      jdbc-url: jdbc:mysql://host:3306/crm_sit
      username: crm_sit
      password: ******
      driver-class-name: com.mysql.cj.jdbc.Driver
      
    # Report 数据库
    report:
      jdbc-url: jdbc:mysql://host:3306/report_sit
      username: report_sit
      password: ******
      driver-class-name: com.mysql.cj.jdbc.Driver
```

## 事务管理

### 单数据源事务

使用 `@Transactional` 注解时，可以指定事务管理器：

```java
// Boss 数据源事务（默认）
@Transactional
public void bossTransaction() {
    // Boss 数据库操作
}

// CRM 数据源事务
@Transactional(transactionManager = "crmTransactionManager")
public void crmTransaction() {
    // CRM 数据库操作
}

// Report 数据源事务
@Transactional(transactionManager = "reportTransactionManager")
public void reportTransaction() {
    // Report 数据库操作
}
```

### 多数据源事务（分布式事务）

如果需要跨多个数据源的事务，建议：

1. 使用消息队列（Kafka）实现最终一致性
2. 使用 Seata 等分布式事务框架
3. 使用 Saga 模式

**注意**: 不建议在一个方法中同时操作多个数据源并期望事务一致性。

## 注意事项

### 1. Mapper 扫描路径

每个数据源的 Mapper 接口必须放在对应的包路径下：

- Boss: `com.xs.boss.infrastructure.persistence.mapper.boss`
- CRM: `com.xs.boss.infrastructure.persistence.mapper.crm`
- Report: `com.xs.boss.infrastructure.persistence.mapper.report`

### 2. PO 对象路径

每个数据源的 PO 对象必须放在对应的包路径下：

- Boss: `com.xs.boss.infrastructure.persistence.po.boss`
- CRM: `com.xs.boss.infrastructure.persistence.po.crm`
- Report: `com.xs.boss.infrastructure.persistence.po.report`

### 3. Mapper XML 路径

每个数据源的 Mapper XML 文件必须放在对应的目录下：

- Boss: `classpath:mapper/boss/*.xml`
- CRM: `classpath:mapper/crm/*.xml`
- Report: `classpath:mapper/report/*.xml`

### 4. 主数据源

Boss 数据源被标记为 `@Primary`，是默认的主数据源。

### 5. 连接池配置

每个数据源都使用 HikariCP 连接池，可以根据实际情况调整连接池参数：

```yaml
spring:
  datasource:
    boss:
      hikari:
        minimum-idle: 5          # 最小空闲连接数
        maximum-pool-size: 20    # 最大连接池大小
        idle-timeout: 600000     # 空闲连接超时时间（毫秒）
        max-lifetime: 1800000    # 连接最大生命周期（毫秒）
        connection-timeout: 30000 # 连接超时时间（毫秒）
```

## 迁移现有代码

如果你有现有的 Mapper 需要迁移到多数据源架构：

1. 确定该 Mapper 应该使用哪个数据源
2. 将 Mapper 接口移动到对应的包路径
3. 将 PO 对象移动到对应的包路径
4. 将 Mapper XML 文件移动到对应的目录
5. 更新所有引用该 Mapper 的代码

## 常见问题

### Q1: 如何添加第四个数据源？

1. 在 `application.yml` 中添加数据源配置
2. 在 `DataSourceConfig` 中添加数据源 Bean
3. 创建对应的 MyBatis 配置类（参考 `BossMyBatisConfig`）
4. 创建对应的 Mapper、PO、XML 目录

### Q2: 为什么 Mapper 扫描不到？

检查以下几点：
1. Mapper 接口是否在正确的包路径下
2. Mapper 接口是否添加了 `@Mapper` 注解
3. MyBatis 配置类的 `@MapperScan` 路径是否正确

### Q3: 如何查看数据源是否配置成功？

启动应用后，查看日志中是否有以下信息：
- HikariPool 初始化日志
- SqlSessionFactory 创建日志
- Mapper 扫描日志
